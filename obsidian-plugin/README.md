# Inkbase — Obsidian 本地语义搜索插件

基于 embedding 向量的语义搜索插件。在 Obsidian 内直接对笔记进行智能检索，所有数据存储在本地。

## 功能

- **语义搜索** — 用自然语言描述你想找的内容，而不是精确关键词匹配
- **库筛选** — 按文件夹划分"搜索对象库"，搜索时可选择只搜某个库
- **自动索引** — 文件保存时自动更新向量索引，无需手动操作
- **多服务商支持** — 豆包（火山方舟）/ Pie Gateway / OpenAI / Ollama / 自定义
- **切换模型保护** — 切换服务商时提示是否清空旧向量数据，避免混用不同模型的向量
- **重建索引强制刷新** — 重建时强制对所有文件重新生成向量，不跳过内容未变的文件

## 安装

1. 下载 `main.js`、`manifest.json`、`styles.css` 三个文件
2. 在 Vault 目录下创建 `.obsidian/plugins/inkbase/` 文件夹
3. 将三个文件放入该文件夹
4. 重启 Obsidian → 设置 → 第三方插件 → 启用 Inkbase

## 使用方式

| 操作 | 入口 |
|------|------|
| 语义搜索 | 侧边栏 🔍 图标 / `Cmd+P` → "Inkbase: 打开语义搜索" |
| 重建全部索引 | `Cmd+P` → "Inkbase: 重建全部索引" |
| 插件设置 | 设置 → 第三方插件 → Inkbase 旁的 ⚙️ 齿轮图标 |

## 设置说明

进入方式：设置 ⚙️ → 第三方插件区域 → Inkbase 右侧齿轮图标

### 1. 大模型配置

选择用于生成文本向量的 Embedding 服务商。

#### 豆包（火山方舟）— 默认推荐

使用火山方舟的多模态 Embedding 模型生成向量。

| 字段 | 说明 | 获取方式 |
|------|------|----------|
| API Key | 火山方舟 API 密钥 | 火山引擎控制台 → 方舟平台 → API Key 管理 |
| 接入点 ID | Embedding 模型的接入点 | 方舟平台 → 接入点管理 → 创建 embedding 模型接入点 |

> **注意**：每位用户需要自己注册火山方舟账号并创建接入点。接入点绑定个人账号，不可共享。

#### Pie Gateway

通过 PieBox 提供的 AI 网关生成向量。文本只在计算时传输，不存储在云端。

| 字段 | 说明 | 获取方式 |
|------|------|----------|
| App ID | PieBox 应用 ID | PieBox 项目 `.piebox/env` 中的 `PIE_APP_ID` |
| App Secret | PieBox 应用密钥 | `.piebox/env` 中的 `PIE_APP_SECRET` |
| 服务地址 | 网关地址，一般不用改 | 默认 `https://pie-gateway.weapp.me` |

#### OpenAI 兼容

支持 OpenAI 官方或任何兼容 OpenAI embedding API 格式的服务。

| 字段 | 说明 | 示例 |
|------|------|------|
| API Key | API 密钥 | `sk-xxxx...` |
| 服务地址 | API 地址（不含 `/v1/embeddings`） | `https://api.openai.com` |
| 模型名称 | embedding 模型名 | `text-embedding-3-small` |

#### Ollama（完全本地）

完全离线，使用本地运行的 Ollama 服务生成向量。隐私性最高。

| 字段 | 说明 | 示例 |
|------|------|------|
| Ollama 地址 | Ollama 服务地址 | `http://localhost:11434` |
| 模型名称 | 已拉取的 embedding 模型 | `nomic-embed-text` |

> 安装：`brew install ollama && ollama pull nomic-embed-text`

#### 自定义服务

用于接入其他任何 OpenAI 格式兼容的 embedding 服务。

| 字段 | 说明 |
|------|------|
| 服务地址 | 完整的 API 地址 |
| API Key | 认证密钥 |
| 模型名称 | 模型名称 |

### 2. 检索设置

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| 自动更新索引 | 开启后，文件每次保存都会自动更新该文件的向量索引 | 开启 |
| 排除检索的文件夹 | 不参与索引的文件夹，用英文逗号分隔多个 | 空 |

**排除文件夹示例**：`模板, .trash, 归档`

---

### 3. 搜索对象库

给 Vault 内的文件夹起一个名字作为搜索分类。搜索时可选择只在某个库内查找。

**添加方式**：

1. 在"库名称"输入框填入显示名（如 `素材库`）
2. 在"对应文件夹"输入框填入 vault 内文件夹路径（如 `素材`）
3. 点击"添加"

**使用效果**：搜索面板顶部会出现筛选按钮 `全部 | 素材库 | ...`，点击切换搜索范围。

**路径规则**：
- 路径相对于 vault 根目录
- 不需要开头的 `/`
- 支持嵌套路径，如 `工作/项目笔记`
- 该路径下所有子文件夹的 .md 文件都会被包含

---

### 4. 索引管理

| 项目 | 说明 |
|------|------|
| 当前索引 | 显示已索引的文档数和片段数 |
| 重建索引 | 重新扫描所有文件并强制重新生成向量 |

> ⚠️ 重建索引会对所有文件重新调用 embedding API，文件较多时耗时较长且消耗 API 额度。

---

### 5. 切换模型

切换 Embedding 服务商时，如果已有索引数据，插件会弹出提示让你选择：

- **清空并切换**（推荐）— 清除旧模型的向量索引数据，之后需要重建索引。只清除向量数据，不会删除你的任何文档。
- **保留并切换** — 保留旧向量数据。适合临时测试不同模型后切回来的场景。

> 不同模型生成的向量维度和空间不同，混用会导致搜索结果不准确。正式切换后务必重建索引。

## 数据存储

| 数据 | 位置 |
|------|------|
| 向量索引 | `.obsidian/plugins/inkbase/inkbase-index.json` |
| 插件设置 | `.obsidian/plugins/inkbase/data.json` |

所有数据存在 vault 本地目录内，不上传到任何服务器。Embedding 服务只在生成向量时传输文本，不存储。

## 常见问题

**Q: 首次使用需要做什么？**

1. 启用插件
2. 在设置中选择 Embedding 服务商并填入凭证
3. `Cmd+P` → "Inkbase: 重建全部索引"
4. 等待索引完成后即可搜索

**Q: 搜索结果不准确？**

- 确保文件已被索引（检查设置中索引管理的文档数）
- 尝试用更自然的语言描述，而非关键词
- 切换过模型后是否重建了索引？

**Q: 索引文件太大怎么办？**

向量索引大小约为每 100 篇文档占用 5-10MB（取决于模型维度）。可以用"排除检索的文件夹"排除不需要搜索的目录。

**Q: 切换服务商后需要重建索引吗？**

是的。插件会在切换时提示你选择清空或保留旧数据。清空后需要重建索引才能搜索。

**Q: 自动索引是什么意思？**

开启后，每次你在 Obsidian 中保存一篇 .md 文件，该文件的向量索引会自动更新。无需手动触发。新建文件、删除文件、重命名文件都会自动处理。
